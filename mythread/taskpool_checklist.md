# mythread 组内线程池（任务队列）验收清单

## 功能验收

- 支持按组创建任务池并挂载到组共享位置（推荐 `gi->locv[slot]`）。
- 支持 GMT 开启 epoch、提交任务、关闭并等待完成的闭环。
- 支持 worker 从队列取任务执行，直到 `open=0 && empty` 后退出本轮并上报完成。
- 支持至少一种队列满策略（阻塞 / 自旋 / 返回失败）且行为明确一致。
- 支持 shutdown 让 worker loop 安全退出，不依赖强制 cancel 才能结束。

## 正确性与并发

- 任务不丢失、不重复执行（提交数=执行数）。
- epoch 不串扰（上一轮残留任务不会被下一轮误执行；或有明确定义的“提交只能在 begin/close 区间”约束）。
- worker 在队列空但 epoch 未关闭时不会永久睡死（能被新任务或 close 唤醒）。
- close 后 worker 能保证 drain 完成再上报完成（GMT wait 后队列为空）。

## 边界条件

- `capacity` 较小（如 8/16）时仍正确。
- 0 任务 epoch（begin 后不 submit，直接 close+wait）可正常完成。
- 队列满时按 flags 处理：
  - 阻塞策略不会死锁（前提条件在文档中说明并在示例遵守）
  - 返回失败策略可被上层检测处理
- detach 前确保无正在执行 epoch（否则返回错误或断言失败的策略明确）。

## 性能与资源

- 不为每个任务做动态内存分配（默认使用固定环形缓冲区）。
- 退避/等待策略不会导致 100% 忙等（若使用自旋，必须含退避）。
- 不引入跨组共享锁，不影响现有绑核/线程创建路径。

## 回归

- 不破坏现有 `StartThreads/EndThreads` 与示例程序行为。
- 分组/非分组两种模式均能编译运行（即便任务池只在分组模式下启用，也需明确且行为一致）。
