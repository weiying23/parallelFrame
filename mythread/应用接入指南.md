# mythread 应用接入指南

## 一分钟了解 mythread

mythread 帮你把计算任务自动分配到 **MPI 进程 → NUMA 线程组 → Worker 线程** 三级并行上。你只需要写计算逻辑，框架负责线程创建、CPU 绑定、同步等待、任务调度。

核心用法只有两种模式，对应两个模板，5 分钟可以跑起来。

---

## 两种模式，选哪个？

| | 模式 A：同步 + 固定划分 | 模式 B：任务池 + 动态调度 |
|---|---|---|
| **适合场景** | 每个线程工作量均匀 | 每个线程工作量不均匀 |
| **硬件** | 同构多核 | 大小核混合（Intel P/E） |
| **负载均衡** | 手动（启动时固定分配） | 自动（谁快谁多干） |
| **开销** | 极低（无锁） | 略高（每任务一次 mutex） |
| **参考文件** | `wave_propagation_ghost_fix.c` | `wave_propagation_ghost.c` |

**简单判断**：不确定选哪个，先用模式 B（任务池），跑起来看性能再决定。

## 模式 A：同步 + 固定划分（5 步上手）

### 完整代码模板

```c
#include "mythread/mythread.h"

/* 第 1 步：定义你的线程数据（每个线程一份） */
typedef struct {
    int y_begin, y_end;   /* 这个线程负责的 Y 范围 */
    double partial_result;
} MyTask;

int _gettdsize_() { return (int)sizeof(MyTask); }  /* 告诉框架你的数据多大 */

/* 第 2 步：定义状态编码（单调递增，避免信号串扰） */
int compute_state(int step) { return step * 2 + 1; }

/* 第 3 步：写 Worker 线程的逻辑 */
void worker_do_compute() {
    MyTask *t = (MyTask*)ti->td;   /* ti 是当前线程的上下文，框架自动提供 */
    for (int y = t->y_begin; y < t->y_end; y++) {
        /* 你的计算核心 */
    }
}

/* 第 4 步：写线程入口（三个角色） */
void thread_run(void) {
    if (ti->igrp < 0) {
        /* === MMT（主管理线程，每个进程一个）=== */
        for (int step = 0; step < N_STEPS; step++) {
            MSG;                    /* 通知所有组：开始计算 */
            MWG;                    /* 等待所有组：计算完成 */
            /* 这里做 MPI 通信 */
        }
    } else if (ti->ind == 0) {
        /* === GMT（组主线程，每组一个）=== */
        for (int step = 0; step < N_STEPS; step++) {
            GWM;  GSS;             /* 等待主线程信号 → 通知组内 worker */
            GWS;  GSM;             /* 等待组内 worker 完成 → 通知主线程 */
        }
    } else {
        /* === Worker（工作线程，每组 N-1 个）=== */
        for (int step = 0; step < N_STEPS; step++) {
            SWG;                   /* 等待组主线程信号 */
            worker_do_compute();   /* 干活 */
            SSG;                   /* 通知组主线程：我做完了 */
        }
    }
}

/* 第 5 步：main 函数 */
int main(int argc, char **argv) {
    MPI_Init(&argc, &argv);
    int mc = -1;

    /* 配置参数：核心数、每组线程数、组数、每节点进程数、管理核心 */
    InitThreads(/*mpi_id*/0, /*NCorePClu*/8, /*NCluPNode*/2,
                /*NCorePGrp*/4, /*NThPGrp*/4, /*NGrpPProc*/2,
                /*NProcPNode*/1, &mc);

    /* 在启动线程前，给每个线程分配 tile */
    for (int g = 0; g < md.ngrp; g++) {
        for (int t = 0; t < md.grps[g]->Nthreads; t++) {
            MyTask *task = (MyTask*)md.grps[g]->threads[t].td;
            task->y_begin = /* ... */;
            task->y_end   = /* ... */;
        }
    }

    StartThreads(thread_run);  /* 启动所有线程 */
    thread_run();              /* MMT 主线程也进入入口函数 */
    EndThreads();              /* 等待所有线程退出 */

    MPI_Finalize();
    return 0;
}
```

### 关键宏速查

```
GWM  = 组主等主线程信号    GSM  = 组主通知主线程完成
GSS  = 组主通知 Worker      GWS  = 组主等 Worker 完成

SWG  = Worker 等组主信号    SSG  = Worker 通知组主完成

MSG  = 主线程通知所有组      MWG  = 主线程等所有组完成
```

## 模式 B：任务池 + 动态调度（6 步上手）

### 完整代码模板

```c
#include "mythread/mythread.h"

/* 第 1 步：定义任务上下文 */
typedef struct {
    int y_begin, y_end;
    int x_begin, x_end;
    double *output_buffer;
} MyTaskCtx;

/* 第 2 步：定义任务执行函数（和模式 A 的计算核心一样，但放在回调里） */
void my_compute_kernel(void *ctx) {
    MyTaskCtx *c = (MyTaskCtx*)ctx;
    for (int y = c->y_begin; y < c->y_end; y++)
        for (int x = c->x_begin; x < c->x_end; x++)
            c->output_buffer[y * NX + x] = /* 你的计算 */;
}

/* 第 3 步：线程入口 — worker 只需要一行 */
void thread_run(void) {
    if (ti->igrp < 0) {
        /* === MMT === */
        for (int step = 0; step < N_STEPS; step++) {
            MSG; MWG;   /* 通知各组计算 → 等待所有组完成 */
        }
    } else if (ti->ind == 0) {
        /* === GMT：管理任务池 === */
        mt_taskpool_attach(0, 512, MT_TASKPOOL_BLOCK);  /* slot=0, 容量=512 */

        for (int step = 0; step < N_STEPS; step++) {
            GWM;                                   /* 等主线程信号 */
            mt_taskpool_begin(0);                  /* 开启本轮 */
            for (int i = 0; i < n_tasks; i++)
                mt_taskpool_submit(0, my_compute_kernel, &task_ctxs[i]);
            mt_taskpool_close(0);                  /* 不再加新任务 */
            mt_taskpool_wait(0);                   /* 等 worker 干完 */
            GSM;                                   /* 通知主线程完成 */
        }

        mt_taskpool_shutdown(0);
        mt_taskpool_detach(0);
    } else {
        /* === Worker：只需要一行 */
        while (!GetLocV(1, 0, NULL)) ntdelay(1);  /* 等 GMT 创建好任务池 */
        mt_taskpool_worker_loop(0);                /* 死循环：等 epoch → 抢任务 → 执行 → 上报 */
    }
}
```

### GMT 调用顺序速查

```
attach(0, 512, BLOCK)         ← 只需一次
   ↓
for each step:
   begin(0)                   ← 开启新轮
   submit(0, fn, ctx) × N     ← 疯狂加任务
   close(0)                   ← 关门
   wait(0)                    ← 等 worker 干完
   ↓
shutdown(0)  →  detach(0)     ← 退出前清理
```

### 队列满的三种策略

| 标志 | 队列满了怎么办 | 什么时候用 |
|------|---------------|-----------|
| `MT_TASKPOOL_BLOCK` | 等着（worker 消费后自动继续） | **推荐，最省心** |
| `MT_TASKPOOL_SPIN` | 自旋重试（不阻塞但不让出 CPU） | 确定马上会有空位 |
| `MT_TASKPOOL_TRY` | 立即返回 -4，你自己处理 | 你打算拆分任务再试 |

## 两层模块体系：按需选

mythread 有 11 个模块，但你不必全用。分层引入：

```
必选（所有应用都需要）
├── mythread.h          聚合头文件
├── mythread_types.h    基础类型（自动包含）
├── mythread_thread.h   线程创建和生命周期
└── mythread_sync.h     同步原语（GWM/GSS/SWG 等）

按需引入
├── mythread_pool.h     任务池（仅模式 B 需要）
├── mythread_decomp.h   域分解（有空间网格时需要）
├── mythread_field.h    NUMA 感知波场分配（stencil/PDE 应用）
├── mythread_halo.h     Halo 交换（有空间网格 + MPI 时需要）
├── mythread_config.h   配置文件解析（独立可用，无线程依赖）
└── mythread_timer.h    TSC 性能计时（调试用）
```

## 常见场景配方

### 场景 1：纯并行循环，无 MPI，无网格

选**模式 A 轻量版**，不分组（`NGrpPProc=1`）：

```c
InitThreads(0, 8,1, 8,4, 1, 1, &mc);  /* NGrpPProc=1 即非分组模式 */

void thread_run(void) {
    if (ti->ind == 0) {             /* tid==0 即主线程 */
        for (int s = 0; s < N; s++) {
            MSS; MWS;               /* 通知 → 等待 worker */
        }
    } else {
        for (int s = 0; s < N; s++) {
            SWM;                    /* 等主线程 */
            /* 干活 */
            SSM;                    /* 干完了 */
        }
    }
}
```

### 场景 2：2D 波动方程（已有 space grid + MPI）

直接用 `wave_propagation_ghost_fix.c` 或 `wave_propagation_ghost.c` 当模板改。

你需要改的地方只有四个回调函数：
- `init_field` — 初始条件
- `compute_interior` — 内部点时间推进
- `compute_boundary` — 边界点时间推进
- `compute_energy` — 能量诊断（不需要可以删）

### 场景 3：有 NUMA 需求的 stencil 应用

分三步引入三层模块：

```
1. mythread_decomp_create()         ← 域分解成 n_groups 个子域
2. group_alloc_field() × n_groups   ← 每组独立分配波场平面（GMT 中调用，bindcpu 后自动 NUMA 绑定）
3. 每步：halo_exchange_intra + halo_exchange_mpi → compute
```

在 GMT 线程中分配，此时 bindcpu 已生效，框架自动选择正确的 NUMA 节点。

### 场景 4：配置参数化

用 `mythread_config` 读 INI 文件，三层优先级（后面的覆盖前面的）：

```
编译默认值  →  config/hardware.cfg  →  环境变量
```

```c
mythread_cfg *cfg = mythread_cfg_load("config/hardware.cfg");
int n_groups = mythread_cfg_get_int(cfg, "", "N_GROUPS", 2);
mythread_cfg_free(cfg);
```

## 常见问题

**Q: 怎么知道线程在哪个角色？**
```c
ti->igrp < 0      → MMT（主管理线程）
ti->ind == 0      → GMT（组主线程）
其他              → Worker
```

**Q: `ti` 和 `gi` 从哪里来？**
框架自动维护的线程局部变量（`__thread`），你直接用，不需要初始化。

**Q: `_gettdsize_()` 是干什么的？**
告诉框架每个线程需要多少字节的私有数据（`ti->td` 指向的空间）。不需要就用默认值。

**Q: 模式和分组模式有什么区别？**
`NGrpPProc > 1` 时为分组模式（每组绑定一个 NUMA 节点，通过 GMT 隔离通信）。
`NGrpPProc = 1` 时为非分组模式（所有线程在一个平坦的池中，适合单 NUMA 或不需要 NUMA 感知的场景）。

**Q: 任务池的 slot 是什么？**
一个槽位编号（0-100），一个组可以有多个任务池（不同阶段用不同池）。通常只用 slot=0。

**Q: MMT 和 GMT 和 Worker 的数量关系？**
- 1 个 MMT（每个 MPI 进程）
- `NGrpPProc` 个 GMT（每个线程组一个）
- `NGrpPProc × (NThPGrp - 1)` 个 Worker

## 从哪开始

1. 看 `mythread接口说明.md` → 了解所有函数
2. 在模式 A（同步）和模式 B（任务池）之间选一个
3. 复制上面的模板代码，替换 `worker_do_compute()` / `my_compute_kernel()` 为你的计算逻辑
4. 如果你有空间网格：参考 `wave_propagation_ghost.c` 或 `wave_propagation_ghost_fix.c`
