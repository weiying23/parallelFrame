# Vibe Implement

## 目标

在不引入额外复杂度的前提下交付可用改动：代码实现 + 运行级验证 + 变更说明。

## 什么时候调用

- 用户已经明确要改什么，或者已有 spec/tasks
- 需要直接动代码：新增接口、修 bug、重构、性能优化

## 实施规则

- 先读再改：先看入口函数、调用者、数据结构与约束
- 小步提交：优先最小可行变更，避免“顺手大改”
- 遵循现有约定：命名、错误处理、线程/锁模型、内存生命周期
- 不新增注释：除非用户要求
- 不引入新依赖：除非仓库已有

## 验证策略（按可用条件选）

- 编译验证：确保项目可构建
- 运行验证：用最小输入/示例触发新路径
- 负面验证：错误输入/边界值不崩溃且行为符合预期

## 交付格式

- 修改点概述（按文件列出）
- 如何使用（参数、调用顺序、示例）
- 如何验证（运行命令或最小复现步骤）
